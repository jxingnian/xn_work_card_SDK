# 目标板部署

## 1. 安装前检查

确认目标板：

- 已烧录我方匹配版本固定固件。
- 系统时间正常。
- `/lib/ld-musl-arm.so.1` 存在。
- SC2356、WS73U WiFi、RTL8723DS UART 蓝牙、BlueZ 和 BlueALSA 固定组件完整。
- 根分区安装前至少有 20 MiB 可用空间；空间不足时禁止上传后再完整解压，必须先清理旧归档或按文件部署。
- `/run` 内存盘至少有 20 MiB 可用空间。
- 当前没有其他程序占用摄像头和海思媒体资源。

正式蓝牙硬件必须按必联 RTL8723D H5 说明连接，不能只接 RX/TX：

```text
核心板 35 UART1_RXD  <- 模组 P42 UART_TX
核心板 37 UART1_TXD  -> 模组 P43 UART_RX
核心板 34 UART1_RTSN -> 模组 P44 UART_CTS
核心板 33 UART1_CTSN -> GND
模组 UART_RTS       -> NC
模组 P34 BT_DIS#    -> 3.3V
```

固定固件中的 `sys_config.ko` 会把核心板 33/34/35/37 配置为 UART1 CTS/RTS/RX/TX。核心板 33 脚已经专用于蓝牙 CTS，不能再作为按键 GPIO；按键必须迁移到其他 GPIO。WS73 只通过 SDIO 提供 WiFi，禁止加载 `ble_soc.ko`；必联 RTL8723DS 只通过 UART1 提供经典蓝牙，禁止启用其 SDIO WiFi。

蓝牙模组采用独立电源时，整机重启必须同步复位模组，保证模组从 115200 的 ROM 初始状态启动。只重启核心板而不复位已经切换到 1.5 Mbps 的模组，会在下一次启动中确定地产生 H5 同步超时。

目标板根分区只有约 81 MiB，禁止把包含 95 MiB x86 工具链的完整客户 SDK 上传到目标板。

## 2. 生成目标板精简包

在开发机的 Ubuntu 或 WSL Bash 中进入 SDK 根目录：

```bash
./scripts/create_target_bundle.sh
```

输出：

```text
dist/workcard-target-1.0.0.tar.gz
dist/workcard-target-1.0.0.tar.gz.sha256
```

在开发机上进入输出目录并校验交付包：

```bash
cd dist
sha256sum -c workcard-target-1.0.0.tar.gz.sha256
tar -tzf workcard-target-1.0.0.tar.gz >/dev/null
cd ..
```

精简包只包含 ARM 服务、客户库、运行库、网络基础组件、Demo 和目标板脚本，不包含 x86 工具链、公开头文件和文档。

## 3. 查询目标板 IP

目标板使用 DHCP，重启后的 IP 可能变化，不能沿用上一次地址。通过调试串口登录后执行：

```sh
ip -4 addr show eth0
ip -4 addr show wlan0
```

选择开发机可以访问的地址。首次连接必须由交付人员通过可信通道核对 SSH 主机指纹，不能长期关闭主机密钥校验。

## 4. 上传和板端校验

在开发机 Ubuntu 或 WSL Bash 中执行：

```bash
scp dist/workcard-target-1.0.0.tar.gz \
    dist/workcard-target-1.0.0.tar.gz.sha256 \
    root@<目标板当前IP>:/run/
```

在目标板 root 终端执行：

```sh
cd /run
sha256sum -c workcard-target-1.0.0.tar.gz.sha256
tar -tzf workcard-target-1.0.0.tar.gz >/dev/null
tar -xzf workcard-target-1.0.0.tar.gz
cd /run/work_card_SDK
```

哈希或归档检查失败时禁止继续安装。

安装完成并重启后执行正式蓝牙验收：

```sh
cd /run/work_card_SDK
./scripts/verify_target_bluetooth.sh
```

验收必须同时通过 `hci0`、`hci_uart`、`rtk_hciattach`、`bluetoothd`、`bluealsad`、WS73 WiFi 和禁止 `ble_soc` 七项检查。

## 5. 旧开发固件首次清理

只有检测到以下旧文件时才执行本节：

```text
/opt/lite-p-stream
/etc/init.d/S90autorun.pre-sc2356
/etc/init.d/S93xingnian_wifi
/etc/init.d/S94lite_p_mqtt
/etc/init.d/S95lite_p_stream
```

执行受保护的旧业务清理：

```sh
CONFIRM_CLEAN_LEGACY=YES ./scripts/clean_legacy_target.sh
```

脚本先把 WS73 和以太网基础服务迁移到 `/opt/workcard-connectivity`，确认新 WiFi 守护启动后，才删除旧 MQTT、媒体程序、旧凭据和旧自启动。脚本保留 bootloader、内核、rootfs、驱动、SSH、BlueALSA 和出厂硬件文件。

该操作不可恢复，详细边界见 `08_旧固件清理与出厂基线.md`。正式客户固件不应包含这些旧文件，因此客户正常部署不执行清理脚本。

## 6. 安装 SDK

在目标板精简包根目录执行：

```sh
./scripts/install_target.sh
```

脚本安装：

```text
/opt/workcard-sdk/bin/workcard-sdk-service
/opt/workcard-sdk/bin/workcard-sdk-supervisor
/opt/workcard-sdk/lib/*
/opt/workcard-sdk/config/*
/opt/workcard-sdk/state
/opt/workcard-connectivity/*
/etc/init.d/S89eth0_dhcp
/etc/init.d/S91workcard_sdk
/etc/init.d/S92workcard_wifi
/etc/init.d/S93bluetooth_audio
/etc/init.d/S94workcard_demo
/usr/bin/bluetoothctl
/opt/bluealsa/bin/bluetoothctl.bin
```

安装完成后自动启动 SDK 服务。`/opt/workcard-sdk/state` 权限固定为 `0700`，用于保存不含 WiFi 明文密码的派生配置。蓝牙包装器会固定 D-Bus 地址和私有库路径，客户无需手工设置环境变量。

## 7. 安装 Demo

```sh
./scripts/install_demo.sh
```

安装结果：

```text
/opt/workcard-demo/workcard-demo
/opt/workcard-demo/workcard-demo.conf.example
/opt/workcard-demo/ca-certificates.crt
```

根据模板创建当前设备的真实配置：

```sh
cp /opt/workcard-demo/workcard-demo.conf.example /opt/workcard-demo/workcard-demo.conf
chmod 0600 /opt/workcard-demo/workcard-demo.conf
vi /opt/workcard-demo/workcard-demo.conf
```

真实 `device_id` 和 `device_secret` 不得放入 SDK 压缩包或系统通用镜像。

## 8. 运行 Demo

```sh
export LD_LIBRARY_PATH=/opt/workcard-sdk/lib:/lib:/usr/lib
/opt/workcard-demo/workcard-demo --config /opt/workcard-demo/workcard-demo.conf
```

正式部署使用 `/etc/init.d/S94workcard_demo` 管理 Demo；该服务在每次开机时由 SysV 按 SDK、WiFi、经典蓝牙、Demo 的顺序启动。Demo 的标准输出和错误输出持久化到 `/opt/workcard-demo/log/workcard-demo.log`，启动和退出状态保存到 `/opt/workcard-demo/log/workcard-demo-exit.log`。

固定 rootfs 的启动框架会直接执行 `S94workcard_demo` 且不传入参数，脚本已将无参数调用定义为 `start`，手工管理时仍使用显式参数。

```sh
/etc/init.d/S94workcard_demo start
/etc/init.d/S94workcard_demo status
/etc/init.d/S94workcard_demo restart
/etc/init.d/S94workcard_demo stop
tail -n 100 /opt/workcard-demo/log/workcard-demo.log
tail -n 50 /opt/workcard-demo/log/workcard-demo-exit.log
```

成功日志至少包含：

```text
底层 SDK 服务已连接
设备=HongOu Lite_P
云端鉴权成功
MQTT连接成功，设备在线状态已发布
```

## 9. 重启验收

完成安装后执行一次受控重启：

```sh
sync
reboot
```

重启后通过串口重新查询 DHCP 地址，再检查：

```sh
/etc/init.d/S91workcard_sdk status
/etc/init.d/S92workcard_wifi status
/etc/init.d/S93bluetooth_audio status
test -c /dev/ttyAMA1
ps | grep '[r]tk_hciattach'
test -d /sys/class/bluetooth/hci0
test -d /sys/module/hci_uart
bluetoothctl --timeout 5 show
bluetoothctl --timeout 5 devices
ps | grep ws73-wifi-worker
test ! -e /opt/lite-p-stream
test ! -e /etc/init.d/S90autorun.pre-sc2356
test ! -e /etc/init.d/S94lite_p_mqtt
test ! -e /etc/init.d/S95lite_p_stream
/etc/init.d/S94workcard_demo status
ps | grep workcard-demo
netstat -tn 2>/dev/null | grep -E ':(443|8883)'
df -h / /run
```

经典蓝牙验收必须同时满足：`/sys/class/bluetooth/hci0` 存在、`/sys/module/hci_uart` 存在、`rtk_hciattach`、`bluetoothd` 和 `bluealsad` 同时运行，并且 `/sys/module/ble_soc` 不存在。精简 rootfs 不依赖 `hciconfig`。

Demo 通过 `/etc/init.d/S94workcard_demo` 开机自启动；云端协议实现仍然属于 Demo 参考应用，客户可以替换为自己的应用，但不得与 Demo 同时占用 SDK 媒体会话。

## 10. 卸载

```sh
./scripts/uninstall_target.sh
```

卸载脚本只删除 `/opt/workcard-sdk`、对应 SysV 服务和运行 Socket，不删除客户应用、客户凭据和固定网络基础组件。
