# 旧固件清理与出厂基线

## 1. 两种操作的边界

`clean_legacy_target.sh` 是旧开发固件到 Work Card SDK 基线的业务清理工具，不是 NAND 擦除工具，也不重新烧录 bootloader、内核或 rootfs。

它用于保证当前可启动目标板不再残留旧 MQTT、旧媒体服务和旧云端凭据。要让客户烧录后与验收板逐文件一致，必须由正式固件构建流程发布固定 rootfs/固件镜像及镜像 SHA-256，不能直接把在线运行设备当作生产镜像来源。

## 2. 明确删除内容

脚本只删除：

```text
/opt/lite-p-stream
/etc/init.d/S90autorun.pre-sc2356
/etc/init.d/S93xingnian_wifi
/etc/init.d/S94lite_p_mqtt
/etc/init.d/S95lite_p_stream
/run/lite-p-mqtt-agent.pid
/run/lite-p-device-stream.pid
/run/lite-p-stream-worker.pid
```

旧目录中的 MQTT 配置、设备云端凭据、媒体配置、旧运行库和旧状态随目录一起删除。`S90autorun.pre-sc2356` 是旧 `fpx1002` 传感器初始化脚本的可执行备份，放在 `S*` 自启动目录会导致冷启动重复加载驱动，因此属于必须清理的旧固件残留。

## 3. 明确保留内容

脚本保留：

- bootloader、环境区、Linux 内核和 UBIFS rootfs。
- `/komod` 中的固定驱动。
- SSH、串口登录和基础网络命令。
- `/opt/bluealsa`、RTL8723DS UART 蓝牙运行文件及 `S93bluetooth_audio`。
- 出厂硬件初始化和测试文件。
- 新 `/opt/workcard-connectivity` 网络基础组件。
- 当前实验室 WiFi 配置，仅用于保持现场 SSH；正式客户镜像不得固化实验室 WiFi 凭据。

## 4. 安全保护

脚本同时要求：

- root 用户。
- `armv7l` 目标架构。
- `/proc/cmdline` 包含固定 `root=ubi0:ubifs`。
- 显式设置 `CONFIRM_CLEAN_LEGACY=YES`。
- 当前 SDK 精简包包含全部新网络组件。

新 WiFi 守护未正常启动时，脚本会尝试恢复旧 WiFi 服务并停止清理，不删除旧业务目录。

## 5. 清理后验收

```sh
test ! -e /opt/lite-p-stream
test ! -e /etc/init.d/S90autorun.pre-sc2356
test ! -e /etc/init.d/S93xingnian_wifi
test ! -e /etc/init.d/S94lite_p_mqtt
test ! -e /etc/init.d/S95lite_p_stream
ps | grep -E 'lite-p-mqtt|lite-p-device|lite-p-stream-worker'
ls -l /opt/workcard-connectivity
df -h /
```

`ps` 检查不应出现旧业务进程。清理完成后必须继续执行 `install_target.sh`，不能把“已清理但尚未安装 SDK”的中间状态交付客户。
