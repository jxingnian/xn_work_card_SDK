# 升级与回滚

## 1. 版本单位

正式发布必须同时记录：

- 固件/rootfs 版本。
- Work Card SDK 版本。
- 公开 ABI 主次版本。
- 硬件组合。
- `MANIFEST.sha256`。

不能只替换 `libworkcard_sdk.so` 而忽略服务和固定 rootfs 版本。

## 2. 升级流程

1. 停止客户应用。
2. 停止 `S91workcard_sdk`。
3. 将 `/opt/workcard-sdk` 备份到同分区版本目录。
4. 校验新包 SHA-256。
5. 执行 `install_target.sh`。
6. 检查服务状态。
7. 运行设备信息、能力、摄像头、音频、WiFi 和蓝牙验收。
8. 验收成功后删除过期备份。

## 3. 回滚流程

升级失败时停止服务，恢复完整旧版 `/opt/workcard-sdk` 和对应 `S91workcard_sdk`，不能混用新客户库和旧服务。

## 4. ABI 规则

- `ABI 1.x`：已有函数、枚举数值和字段语义保持兼容。
- 新结构字段只能追加到尾部。
- 不兼容修改必须升级 ABI 主版本和 SONAME。
- 客户应用启动后应读取设备和 ABI 版本并记录。

## 5. 实机验收

升级或回滚都必须在目标硬件执行：服务启动、H.264 首个 IDR、持续音视频、下行对讲、WiFi 重连、蓝牙 A2DP 和进程退出资源释放。
