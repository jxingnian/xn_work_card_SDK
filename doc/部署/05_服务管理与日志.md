# 服务管理与日志

## 1. 服务命令

```sh
/etc/init.d/S91workcard_sdk start
/etc/init.d/S91workcard_sdk stop
/etc/init.d/S91workcard_sdk restart
/etc/init.d/S91workcard_sdk status
/etc/init.d/S94workcard_demo start
/etc/init.d/S94workcard_demo stop
/etc/init.d/S94workcard_demo status
```

## 2. 运行文件

| 路径 | 用途 |
| --- | --- |
| `/run/workcard-sdk/service.sock` | 无客户连接时发布的本地 IPC 监听路径 |
| `/run/workcard-sdk-supervisor.pid` | SDK supervisor PID |
| `/run/workcard-sdk-service.pid` | 真实 SDK 服务 PID |
| `/tmp/workcard-sdk-service.log` | 不含客户凭据的服务日志 |
| `/tmp/workcard-sdk-service-exit.log` | 每次启动、退出时间和退出状态 |
| `/tmp/workcard-wifi-*.log` | WiFi 命令诊断 |
| `/tmp/workcard-bluetooth-*.log` | 蓝牙命令诊断 |
| `/opt/workcard-demo/log/workcard-demo.log` | Demo MQTT、WSS、SDK 和媒体业务日志 |
| `/opt/workcard-demo/log/workcard-demo-exit.log` | Demo 启动、缺配置、停止超时和退出状态日志 |

## 3. 单客户端规则

第一版只支持一个客户应用独占 SDK 服务。新应用启动前应确保旧应用已经退出。客户连接成功后服务会删除监听路径，阻止第二个客户进入等待队列；客户退出或崩溃后服务释放媒体资源并重新发布 Socket。

真实服务异常退出时 supervisor 只记录退出状态并写入 `/run/workcard-sdk/reboot.required`，不会在媒体 HAL 状态未知时原地拉起服务。该标志存在时必须整板冷启动，禁止手工删除标志后重启服务。

## 4. 日志检查

```sh
tail -n 100 /tmp/workcard-sdk-service.log
tail -n 20 /tmp/workcard-sdk-service-exit.log
tail -n 100 /tmp/workcard-wifi-reconfigure.log
tail -n 100 /tmp/workcard-bluetooth-action.log
tail -n 100 /opt/workcard-demo/log/workcard-demo.log
tail -n 50 /opt/workcard-demo/log/workcard-demo-exit.log
```

日志不得包含 `device_secret`、WiFi 密码、MQTT 密码和完整鉴权消息。提交现场日志前仍应由客户检查敏感信息。

## 5. 资源检查

```sh
ps | grep workcard-sdk-service
ps | grep workcard-demo
cat /proc/modules | grep -E 'plat_soc|wifi_soc|hci_uart|ble_soc'
ps | grep '[r]tk_hciattach'
test -d /sys/class/bluetooth/hci0
test -d /sys/module/hci_uart
```

正式状态必须包含 `plat_soc`、`wifi_soc` 和 `hci_uart`，并且 `/sys/class/bluetooth/hci0` 存在。如果出现 `ble_soc`，说明错误启用了 WS73U 蓝牙，当前固件不得通过验收。

只有在没有客户应用连接时才使用 `ls -l /run/workcard-sdk/service.sock` 检查监听状态。
