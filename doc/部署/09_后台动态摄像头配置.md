# 后台动态摄像头配置

## 1. 功能边界

客户 Demo 已实现后台 MQTT Desired 摄像头配置接收，不需要恢复旧 MQTT Agent。后台配置页面提交后，设备会验证参数、重建一次摄像头媒体会话，并通过 MQTT 返回实际生效结果。

当前支持：

| 参数 | 范围 |
| --- | --- |
| 宽度 | 160-1600，必须为偶数 |
| 高度 | 120-1200，必须为偶数 |
| 帧率 | 1-30 fps |
| GOP | 1-300 |
| 码率 | 64000-4000000 bps |

当前音频参数仍按固定硬件能力运行，不在摄像头动态配置范围内。

## 2. 后台操作流程

1. 打开后台“设备配置”。
2. 选择 MQTT 在线设备。
3. 在“视频参数”中填写宽度、高度、帧率、GOP 和码率。
4. 点击“提交设备配置”。
5. 等待页面从“等待设备确认”变为“已生效”。
6. 页面同时显示 Desired revision 和 Reported revision 相同。

设备离线时后台仍会保留 Retained Desired；设备重新上线后会自动接收并应用最新配置。

## 3. 设备处理流程

设备订阅：

```text
v1/devices/{device_id}/config/desired
```

设备处理成功后发布：

```text
v1/devices/{device_id}/config/result
v1/devices/{device_id}/config/reported
```

设备会将最后一次硬件验证成功的 revision 和视频参数原子保存到：

```text
/opt/workcard-demo/camera-state.conf
```

应用重启时先加载该状态，再启动摄像头，保证重启不会回退到配置模板中的旧参数。

## 4. 结果状态

| 状态 | 含义 |
| --- | --- |
| `applied` | 摄像头已停止并按新参数重新启动，状态文件已保存 |
| `rolled_back` | 新参数启动或状态保存失败，设备已恢复上一份配置 |
| `failed` | JSON、revision 或参数校验失败 |

后台设备列表中的媒体参数来自 WSS 鉴权上报；动态配置成功后 Demo 会请求 WSS 安全重连，使列表中的分辨率和帧率同步刷新。

## 5. Revision 规则

设备正常运行期间要求 `baseRevision` 等于当前已生效 revision。首次安装 Demo 且设备没有本地状态文件时，设备允许以后台 Retained Desired 的 `baseRevision` 建立初始基线，然后应用更高的 Desired revision。

禁止手工修改 `camera-state.conf` 或删除 revision。需要恢复配置时，应通过后台页面提交新的完整视频参数。

## 6. 故障检查

```sh
tail -n 100 /tmp/workcard-demo.log
cat /opt/workcard-demo/camera-state.conf
netstat -tnp | grep 8883
```

如果页面长时间停留在“等待设备确认”，先确认 MQTT TLS 连接、Demo 日志和状态文件权限；不要直接强制杀死底层 SDK 服务。
