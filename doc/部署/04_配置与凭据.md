# 配置与凭据

## 1. 边界

SDK 不保存和管理云端设备凭据。`device_id`、`device_secret`、MQTT 账号和客户业务 Token 全部属于客户应用。

Demo 同时演示当前 WSS 和 MQTT TLS 应用接入。WSS 使用 `device_id` 与 `device_secret`；MQTT 使用后台为每台设备独立签发的 `mqtt_username` 与 `mqtt_password`，两套凭据不能混用。

## 2. Demo 配置

模板位于：

```text
demo/config/workcard-demo.conf.example
```

必填敏感字段：

```ini
device_id=
device_secret=
mqtt_host=iot.xingnian.vip
mqtt_port=8883
mqtt_username=
mqtt_password=
wired_interface=eth0
wired_gateway=192.168.10.1
network_switch_timeout_seconds=30
wifi_state_file=/opt/workcard-demo/wifi-state.conf
```

TLS 配置：

```ini
server_url=wss://iot.xingnian.vip/device-stream
ca_file=/opt/workcard-demo/ca-certificates.crt
```

MQTT Demo 使用 TLS 端口 `8883`，连接后会向 `v1/devices/{device_id}/presence` 发布 retained 在线状态，并设置离线遗嘱；后台设备列表依赖该状态判断在线。客户应用可直接复用 `demo/src/mqtt`，也可以替换为自己的 MQTT 客户端，但必须保持后台协议约定。

MQTT 账号由后台按设备签发，不能把服务器上的账号复制给其他设备。生产部署时通过安全传输方式写入配置文件，完成后设置 `0600` 权限。

## 3. 权限

```sh
chown root:root /opt/workcard-demo/workcard-demo.conf
chmod 0600 /opt/workcard-demo/workcard-demo.conf
chmod 0644 /opt/workcard-demo/ca-certificates.crt
```

## 4. 禁止事项

- 禁止将真实凭据写入 `.c`、`.h`、CMake 或构建脚本。
- 禁止在日志中打印鉴权 JSON。
- 禁止把真实配置加入版本库或 SDK 压缩包。
- 禁止使用跳过证书校验的 TLS 模式。
- 禁止所有设备共用同一个设备密钥。

## 5. WiFi 密码

WiFi 密码通过 `workcard_wifi_connect` 传给服务。服务使用 WPA2 标准 PBKDF2-HMAC-SHA1 派生 PSK，持久化状态不保存明文密码。客户应用也不得在日志中输出该结构。

SDK 派生状态固定保存在：

```text
/opt/workcard-sdk/state/wifi-profiles.json
/opt/workcard-sdk/state/wpa-supplicant.conf
```

目录权限为 `0700`，文件权限为 `0600`。系统联网守护位于 `/opt/workcard-connectivity`，其中 `wifi.conf` 是固定固件初始联网配置，不属于客户应用 SDK 配置。

Demo 的 `wifi_state_file` 只保存后台配置清单的公开元数据，用于完整替换时删除已取消、禁用或改名的旧网络。保存配置不会主动连接；只有后台独立连接动作才会调用 `workcard_wifi_connect`。连接前 Demo 验证有线网关和 MQTT Broker TCP 端口，失败时不修改当前 WiFi 路由。
